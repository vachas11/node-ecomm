📁 Node E-Commerce - Architecture & Folder Structure

Quick Summary: A microservices monorepo with 2 services (API Gateway + User Service), each following a 3-layer architecture (Controller → Service → Repository → Prisma ORM → PostgreSQL). Includes shared authentication utilities, comprehensive documentation, and a full monitoring stack.

🎯 Service Breakdown

🚪 API Gateway (Port 3000)

Purpose: Entry point for all external requests
  • Routing: Proxies requests to appropriate microservices
  • Authentication: Handles login, token refresh, logout
  • Rate Limiting: Prevents API abuse
  • Resilience Patterns: Circuit Breaker, Retry Strategy, Bulkhead Isolation
  • Token Management: Stores refresh tokens in database
Database: Prisma ORM → PostgreSQL (refresh_tokens table)

👤 User Service (Port 3001)

Purpose: User management and authentication backend
  • User Registration: Create new user accounts
  • Authentication: Validate credentials, hash passwords
  • Profile Management: Update user information
  • Internal API: Service-to-service user validation
Database: Prisma ORM → PostgreSQL (users table)

🔄 Layered Architecture (Inside Each Service)

┌─────────────────────────────────────────────┐
│          Controllers (HTTP Layer)        │  ← Handle requests/responses
│   • Parse request body/params              │
│   • Call service methods                   │
│   • Return JSON responses                  │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│       Services (Business Logic Layer)    │  ← Orchestrate operations
│   • Validation (password strength, email)  │
│   • Business rules enforcement             │
│   • Transaction orchestration              │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│      Repositories (Data Access Layer)    │  ← Database operations only
│   • CRUD operations via Prisma             │
│   • Query building                         │
│   • Data transformation                    │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│            Prisma ORM                   │  ← Type-safe database access
│   • Auto-generated TypeScript client       │
│   • Type safety & autocomplete             │
│   • Parameterized queries (SQL injection)  │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│            PostgreSQL                   │  ← Database
└─────────────────────────────────────────────┘

📦 What Each Folder Contains

src/controllers/

Purpose: HTTP request/response handling

  • Parse incoming requests (body, params, headers)
  • Delegate to service layer
  • Format and return JSON responses
  • Rule: No business logic here, only HTTP handling

src/services/

Purpose: Business logic and orchestration

  • Input validation (password strength, email format)
  • Business rules (check if email already exists)
  • Orchestrate multiple repository calls
  • Transaction management
  • Rule: No HTTP code, no direct database access

src/repositories/

Purpose: Database operations only

  • CRUD operations using Prisma
  • Query building (filters, sorting, pagination)
  • Data transformation (DB format ↔ Domain models)
  • Rule: No business logic, no HTTP code

src/models/

Purpose: Data models and domain logic

  • TypeScript interfaces and classes
  • Domain methods (getFullName(), isAdmin())
  • Data transformation (toJSON())

src/routes/

Purpose: API route definitions

  • Map HTTP methods + paths to controllers
  • Apply middleware (authentication, validation)
  • Group related routes

src/middleware/

Purpose: Request processing pipeline

  • Authentication checks
  • Request validation
  • Proxy logic (API Gateway)
  • Error handling

src/lib/

Purpose: Resilience and reliability patterns (API Gateway only)

  • CircuitBreaker.ts: Prevent cascading failures
  • RetryStrategy.ts: Retry failed requests with backoff
  • BulkheadIsolator.ts: Resource isolation
  • ConnectionPool.ts: Connection management
  • Metrics.ts: Performance monitoring

prisma/schema.prisma

Purpose: Database schema definition

  • Define models (tables)
  • Field mappings (camelCase ↔ snake_case)
  • Indexes and constraints
  • Generate TypeScript client

🔗 Shared Code

shared/auth/

Purpose: Reusable authentication utilities across all services

  • jwt.ts: Generate & verify JWT tokens
  • blacklist.ts: Manage revoked tokens (Redis)
  • middleware.ts: Express authentication middleware
  • rateLimiter.ts: Rate limiting implementation (Redis)

Why shared? Prevents code duplication, ensures consistency

📊 Architecture Highlights

  • ✅ Microservices: Independent services, separate databases
  • ✅ Monorepo: Shared dependencies via npm workspaces
  • ✅ Layered Architecture: Clean separation of concerns
  • ✅ Repository Pattern: Abstraction over Prisma for testability
  • ✅ Type Safety: TypeScript + Prisma for compile-time checks
  • ✅ Resilience: Circuit breaker, retry, bulkhead patterns
  • ✅ Observability: Metrics, logging, monitoring dashboards
  • ✅ Security: JWT auth, rate limiting, token blacklist
  • ✅ Documentation: 60+ deep-dive modules for interview prep
  • ✅ Production-Ready: Docker, CI/CD, health checks
